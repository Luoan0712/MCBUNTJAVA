# SYS-CHAT · 聊天治理

> **范围**：本插件对公共聊天执行禁言和防刷屏的判定、玩家反馈与状态边界。
> **不在本文**：手动处罚命令与时长语法见 [SYS-COMMANDS](SYS-COMMANDS-命令与权限.md)；持久化、配置键和线程机制见 [ENG-ARCH](../engineering/ENG-ARCH-架构与数据.md)。
> **查阅**：先读 §0；判定看 §2，触发动作看 §3，线程接入看 §4。

## 0 结论

- 基础版治理公共聊天；私聊、命令输出和第三方频道的边界见 §1。
- 对同一条消息先判断禁言，再判断防刷屏；按 UUID 管理玩家状态，不共享中转 IP 状态（§2）。
- 防刷屏默认取消触发消息；自动处罚、警告与踢出都先取消原消息（§3）。
- 异步聊天监听不执行磁盘 I/O 或非线程安全 Bukkit 操作，不通过重广播伪造原聊天（§4）。

### 0.1 接入要点

- **处理公共聊天**：已被其他插件取消的消息不恢复，也不再次处罚；命中本插件规则后只处理一次（§1、§2）。
- **读取禁言**：使用可供并发读取的有效状态和绝对到期时间；到期直接放行，不等待清理落盘（§2）。
- **接入自动处罚**：回到主线程调用统一服务，共用持久化、反馈和日志，不独立维护第二套禁言（§3、§4）。

## 1 作用范围

公共聊天指 Paper `AsyncChatEvent` 中正常发送给聊天接收者的玩家消息。v1 不拦截 `/msg`、`/tell`、`/w`、`/me`，也不承诺管理第三方聊天插件另建的频道。新增覆盖渠道先修改本契约并补对应验收。

手动禁言对所有玩家生效，包括 OP。`mcbunt.admin.antispam.bypass` 只豁免防刷屏，不豁免禁言；默认授予 OP，并纳入插件总权限显式子节点。

消息判定只影响当前玩家；共享 IP 的玩家使用独立状态。未触发规则的消息保留原消息组件、签名与接收者，不改写成插件系统广播。

## 2 判定与窗口

### 2.1 判定顺序

1. 消息已被取消时停止处理。
2. 存在未到期禁言时取消消息，并向发送者提示理由与剩余时间；本次不累计防刷屏状态。
3. 有防刷屏豁免时放行，不累计防刷屏状态。
4. 清理过期窗口记录，先检查频率，再检查重复；命中任一项即执行 §3，多个命中只计一次触发。
5. 放行时登记本条的时间及规范化文本，交回 Paper 正常发送。

### 2.2 规则默认值

| 规则 | 工程默认与边界 |
|---|---|
| 滑动窗口 | `5` 秒，以单调时钟计算 |
| 窗口内最多消息数 | `4` 条；第 `5` 条触发 |
| 重复检测 | 开启；与窗口内上次被本插件放行的消息比较 |
| 重复文本规范化 | Unicode NFKC、去首尾空白、连续空白合并为空格、Locale.ROOT 小写 |
| 默认动作 | `cancel` |
| 自动禁言时长 | `120` 秒 |

窗口为 `(当前时间－窗口长度, 当前时间]`；恰好到达左边界的记录移除。只保存本插件放行的消息；被拦截的尝试不延长窗口，也不把被拒文本变成下次比较基准。被本插件放行后又被其他插件取消的情况，不承诺回滚本次统计。

规范化只用于重复比较，不修改原聊天内容。两条不同消息不因共用 IP 而互相命中；同一玩家重连也不清空仍有效的窗口记录。离线且窗口记录全部过期后回收该玩家的临时状态；重启后防刷屏窗口从空状态开始，禁言仍按持久化记录生效。

## 3 触发动作与审计

| 动作 | 处理结果 |
|---|---|
| `cancel` | 取消触发消息，不给玩家额外警告 |
| `warn` | 取消触发消息，向发送者提示触发原因 |
| `mute` | 取消触发消息，经统一禁言服务施加自动禁言并反馈 |
| `kick` | 取消触发消息，主线程踢出目标并反馈原因 |

自动禁言的到期时间取现有到期时间与本次自动禁言到期时间中较晚者；永久禁言不被缩短。无需延长时不覆盖既有理由和操作者，审计记录触发但不伪造第二次处罚。若玩家在异步判定后已离线，踢出动作记 `NO_CHANGE`；自动禁言仍可作用于可信已知 UUID。

每次触发记录一次 `antispam` 审计，区分频率或重复原因、配置动作与执行结果。若统一处罚服务另写 `mute` 或 `kick` 记录，应能关联为同次触发，不能重复施加动作。被手动禁言者每次尝试发言不另写管理处罚日志，避免把聊天尝试当重复管理操作。

## 4 异步接入边界

使用 Paper `AsyncChatEvent` 取消违规消息。该事件可能在异步线程触发，Bukkit 操作需按 API 线程限制调度；官方说明见 [Paper Chat events](https://docs.papermc.io/paper/dev/chat-events/)。

异步路径只做消息取消、纯文本规范化、基于 UUID 的线程安全判定以及读取禁言和豁免快照。磁盘写入、踢出、自动禁言状态变更及玩家反馈交给主线程或其统一写入流程；不能在异步事件中等待主线程，再等主线程反过来等待事件。

豁免快照由主线程维护，权限变更在下次快照刷新后生效；具体刷新时机由 ENG-ARCH 规定。管理命令仍逐次执行实时权限校验，不复用聊天豁免快照授权处罚。

一名玩家的“检查窗口—判断—登记”是不可分割的操作，不能只靠线程安全 Map 而让内部队列并发修改。安排自动动作前登记本次触发，避免同一消息重入导致多次处罚。监听结束前决定是否取消；不能等异步动作完成后再尝试撤回已经发出的聊天。
