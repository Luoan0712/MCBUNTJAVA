# SYS-COMMANDS · 命令与权限

> **范围**：本插件管理入口、权限、玩家可见结果、处罚与倒计时重启的外部契约。
> **不在本文**：配置键、存储与线程机制见 [ENG-ARCH](../engineering/ENG-ARCH-架构与数据.md)；聊天判定见 [SYS-CHAT](SYS-CHAT-聊天治理.md)。
> **查阅**：先读 §0；命令看 §1，身份与处罚看 §3，重启看 §4。

## 0 结论

- 用户常用命令直接进入本插件；原生命令与别名的接管边界见 §2，不要求管理员改用 `m` 前缀。
- 玩家处罚只使用服务器可信玩家身份；不得以中转 IP 识别或连带处罚玩家（§3）。
- 所有插件入口共用权限检查、业务处理与审计；`/tps` 保留 Paper 实现（§1、§2）。
- 本文补齐的默认文案、重启参数和边界行为属于工程默认；来源状态以 [REG-STATE](../registry/REG-STATE-决策与开发状态.md) 为准。

### 0.1 接入要点

- **接入命令**：共享同一业务处理，覆盖玩家、控制台及 RCON；命令方块不在支持范围（§1、§2）。
- **变更处罚**：先校验参数、权限与身份，再变更状态；持久化结果按 ENG-ARCH 判定，不把失败回复成成功（§3）。
- **修改重启**：只允许一个倒计时，使用优雅停服与外部拉起；插件停用不主动触发停服（§4）。

## 1 命令与权限表

`<参数>` 必填，`[参数]` 可省；理由或公告正文包含其后全部文字。插件权限前缀为 `mcbunt.admin.`，表中只列后缀。

| 命令 | 权限后缀 | 成功结果 |
|---|---|---|
| `/kick <玩家> [理由]` | `kick` | 踢出在线目标，回复操作者并记录日志 |
| `/ban <玩家> [时长] [理由]` | `ban` | 新增或替换玩家封禁；在线目标立即断开 |
| `/pardon <玩家>`、`/unban <玩家>` | `unban` | 解除同一玩家的封禁，两入口语义相同 |
| `/mute <玩家> [时长] [理由]` | `mute` | 新增或替换公共聊天禁言 |
| `/unmute <玩家>` | `unmute` | 解除公共聊天禁言 |
| `/muteinfo <玩家>` | `muteinfo` | 显示是否禁言、理由、操作者、到期时间及剩余时长 |
| `/online`、`/list` | `online` | 显示当前在线人数、人数上限与玩家名称列表 |
| `/restart [秒数]`、`/restart cancel` | `restart` | 安排或取消重启，见 §4 |
| `/broadcast <正文>` | `broadcast` | 向全体在线玩家发送公告，控制台同时留记录 |
| `/tps` | Paper 原生节点 | 显示 Paper 原生性能结果；不新增采集器 |

插件权限节点全部 `default: op`，并以 `mcbunt.admin.*` 显式列出子权限；`*` 本身不靠字符串约定自动生效。控制台和 RCON 是管理入口，调用同一服务；记录操作者类型，不能把 RCON 误记成某位 OP 玩家。

普通玩家默认无上述插件权限。OP 仍可被有权限者封禁、禁言或踢出，不设置隐含的处罚豁免。防刷屏豁免只由 SYS-CHAT 规定。查询命令不广播；`muteinfo` 不提供无权限自查特例。

`/tps` 的实际原生权限和输出由目标 Paper 提供，在部署验收中核实；声明 `mcbunt.admin.tps` 不会自动改变原生命令权限。v1 不要求 `/reload`、配置热重载或 `m` 前缀兼容命令。

## 2 命令接管与入口一致性

| 入口 | 本插件的责任 |
|---|---|
| `/ban`、`/pardon`、`/kick`、`/restart`、`/list` | 接管同名短命令，不依赖加载顺序碰运气 |
| `/unban`、`/mute`、`/unmute`、`/muteinfo`、`/online`、`/broadcast` | 提供插件命令；同义入口共享权限与业务处理 |
| `mcbuntadmin:` 插件命名空间入口 | 与短命令同一权限、结果和日志，不重复执行 |
| `minecraft:ban`、`minecraft:kick`、`minecraft:pardon` | 纳入对应插件处理，避免绕过时长语义与审计 |
| 目标服务器仍可用的原生重启入口 | 纳入同一倒计时处理；具体标签在环境核实后登记 |
| `/tps` 及其 Paper 原生命名空间入口 | 维持 Paper 行为，验收其实际权限 |

只有表内管理入口属于接管范围；不改写普通聊天、其他插件命令或任意带冒号的输入。`/say` 保留原生行为，不冒充 `/broadcast`。本插件不注册、不调用封 IP 命令；原生 IP 管理入口不转成玩家处罚。

原生命名空间也在运行时命令树中接管，因此 `execute run minecraft:ban` 等运行时嵌套调用共用插件校验与审计。启动时已解析并缓存原生节点的数据包函数不承诺被追溯替换，本版不新增数据包管理能力。

优先使用 Paper 公共命令注册能力。同名主标签能够覆盖已有命令，但别名不会覆盖已有标签，因此 `/pardon`、`/list` 即便与新命令同义，也应独立注册主标签并共享执行器。注册结果与最终可执行行为都要验收。[Paper Commands API](https://jd.papermc.io/paper/26.3/io/papermc/paper/command/brigadier/Commands.html)

## 3 玩家身份、时长与处罚结果

### 3.1 身份解析

- 在线目标使用当前服务器提供的 UUID 和 Profile；离线目标只接受可信已知身份，包括已有处罚记录中的 UUID。
- 名称大小写不造成重复身份；名称只用于查找和显示，处罚以 UUID 关联。
- 从未出现且无法可靠解析的名称，返回“无法确认玩家身份”，不捏造 UUID，不写入假成功处罚。
- 可信 UUID 的来源依服务器登录验证及代理转发配置核实；中转 IP 本身不能证明 UUID 已正确转发。纯离线模式改名后身份可能变化，不承诺自动关联。
- `/kick` 的离线目标返回“玩家不在线”；其余处罚与查询可处理已知离线身份。不以 IP 查询或处罚玩家。

### 3.2 时长与理由

| 项目 | 默认值或有效格式 |
|---|---|
| ban 省略时长 | `perm`，永久 |
| mute 省略时长 | `30m` |
| 有限时长 | 正整数加一个小写单位：`s`、`m`、`h`、`d`；一天按 24 小时 |
| 永久时长 | `perm` |
| ban 默认理由 | `违反服务器规则` |
| mute 默认理由 | `违反聊天规则` |
| kick 默认理由 | `管理员已将你移出服务器` |

不支持复合时长；`1h30m`、`0m`、负数、裸数字和计算溢出返回参数错误，不执行处罚。目标后的首词若符合数字或带正负号数字开头的时长形状，应先按时长校验；例如 `2hh` 不能悄悄当理由并执行永久封禁。理由本身以这类词开头时，先显式给出合法时长，例如 `/ban Alex perm 123 次违规`。

示例：`/ban Alex 2h 恶意破坏`、`/ban Alex 恶意破坏`、`/mute Alex 15m 刷屏`。默认文案可配置，时长规则与参数错误不能由文案配置改变。

有限处罚在操作成功时计算绝对到期时间；服务器离线期间仍计时。到期后的登录或聊天判定不再处罚，不能等待清理任务才放行。精确存储格式见 ENG-ARCH。

### 3.3 变更与反馈

重复 `/ban` 或 `/mute` 明确替换已有到期时间、理由和操作者；自动防刷屏禁言另按 SYS-CHAT 的“不缩短既有处罚”处理。`/unban`、`/unmute` 无有效处罚可解除时返回 `NO_CHANGE`，不广播虚假的解除结果。

管理变更成功后公告一次，包含目标、动作、理由及永久或到期信息；踢出反馈包含理由。失败或无变化只回复操作者。审计结果的取值、字段与落盘失败语义由 ENG-ARCH「操作日志」统一规定。

公告和用户提供的理由作为纯文本显示，不解析 MiniMessage 标签、点击执行命令或嵌入动作。`/broadcast` 空正文报错。公告给在线玩家显示固定前缀 `【公告】`；处罚公告与命令回执不重复发送同一条全服广播。

## 4 倒计时重启

| 参数或行为 | 工程默认 |
|---|---|
| 省略秒数 | `60` 秒 |
| 显式秒数 | `1`～`86400` 的整数；零、负数、小数、溢出均拒绝 |
| 提醒节点 | 剩余 `60、30、10、5、4、3、2、1` 秒 |
| 取消入口 | `/restart cancel`，与安排共用 restart 权限 |

安排成功立即公告总等待秒数和可取消状态；之后只发送实际经过的提醒节点。开始公告与同一秒节点合并为一条，不补发开始前已过的节点。服务器短暂停顿跳过多个节点时，只发送当前剩余秒对应的提醒，不瞬间补发旧提醒。

倒计时以单调时钟计算真实经过时间，在主线程调度检查；不能把固定 tick 数当成精确秒数。到期只进入一次执行流程：公告、完成处罚数据保存并尝试刷新日志、调用服务端优雅停服，由已验证的外部守护重新启动进程。处罚数据保存失败时取消本次重启并提示操作者；单纯审计写入失败按 ENG-ARCH 的有界刷新与降级规则处理，不无限阻止停服，也不假称已完成重启。

已有倒计时时再次安排，返回“已有重启计划”，不覆盖原计划；只有权限检查通过的取消请求可撤销。没有计划时取消返回 `NO_CHANGE`。执行停服已经开始后不再接受取消。

插件停用时取消未到期任务并清理资源，不在 `onDisable` 再次发起停服；服务器重新启动后不恢复旧倒计时。安排、取消、开始执行、执行失败分别进入审计。真正“重启成功”由进程重新启动和玩家重新连接的部署验收确认，插件停服前的回执只能说明已开始执行。
