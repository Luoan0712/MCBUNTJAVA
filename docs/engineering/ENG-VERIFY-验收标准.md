# ENG-VERIFY · 验收标准

> **范围**：规定功能交付时要验证的用户可见行为和结果记录方式。
> **不在本文**：命令语义与权限见 [SYS-COMMANDS](../design/SYS-COMMANDS-命令与权限.md)，聊天判定见 [SYS-CHAT](../design/SYS-CHAT-聊天治理.md)，配置、数据与日志见 [ENG-ARCH](ENG-ARCH-架构与数据.md)，部署步骤见 [OPS-DEPLOY](../operations/OPS-DEPLOY-部署与重启.md)。
> **查阅**：命令看 §2，聊天与权限看 §3，真实重启看 §4，数据及交付看 §5。

## 0 结论

- 实际执行状态只在 REG-STATE 登记；本文中的步骤不代表已有可运行插件。
- 按受影响功能选择检查，首次完整交付执行本文全部适用项目；纯文档修改只检查文档引用与一致性。
- 处罚、聊天、权限和真实重启要在测试服务器验证；构建成功或 RCON 命令成功不能代替这些结果。
- 通过、失败、未执行、环境不适用分别记录；缺失结果不能记为通过，环境不适用写明原因。

### 0.1 接入要点

- 改命令、配置或聊天规则时，同批检查本文对应情景是否仍符合权威设计。
- 执行前读取 [REG-STATE](../registry/REG-STATE-决策与开发状态.md) 的实际状态，确认测试服务器、测试账号和身份模式。
- 执行后只把实际结果写入 REG-STATE；保留能定位问题的命令、响应和日志路径即可。

## 1 环境与快检

1. 源码到位后，用项目的 Gradle Wrapper 构建；检查 JAR 包含插件描述与默认配置，且不把 Paper 服务端实现打入插件。
2. 在目标 Paper 与 Java 环境加载 JAR；确认无插件加载错误，所有约定入口可发现，普通玩家看不到或无法执行无权限管理入口。
3. 准备管理员、无管理权限玩家，以及经同一中转出口连接的两个不同身份玩家；另准备有历史记录的离线身份和无法解析的名字。
4. 记录实际服务端版本、Java 版本、现有插件及代理身份方式；测试使用的参数直接读取权威配置，不在验收文档另设一份默认值。

## 2 命令与处罚

| 编号 | 情景 | 预期结果 |
| --- | --- | --- |
| V-01 | 用 `/kick` 踢在线玩家；再指定离线玩家 | 在线目标立即断开并看到理由；离线目标明确失败；结果与日志一致 |
| V-02 | `/ban` 省略时长、指定有效时长、指定非法时长 | 分别按 SYS-COMMANDS 处理；非法输入不修改已有处罚；在线被封目标立即断开 |
| V-03 | 封禁已知离线身份；尝试封禁无法解析的名字 | 已知身份生效；未知身份明确拒绝，不生成随意 UUID，不退回 IP 封禁 |
| V-04 | 被封玩家重新登录、服务器重启后再登录；等待临时封禁到期 | 未到期仍拒绝；到期可登录；按玩家身份关联，不按连接 IP 关联 |
| V-05 | 分别用 `/pardon`、`/unban` 解封，并对未封目标执行 | 两入口共用 unban 权限与同一服务；解除后可登录；无现存处罚时按命令契约明确反馈 |
| V-06 | 用 `/mute` 禁言在线玩家和已知离线身份 | 公共聊天被阻止；生效范围及到期行为符合 SYS-CHAT；离线处罚在登录后生效 |
| V-07 | 禁言玩家退出重进、服务器重启、时间到期 | 未到期禁言保留；到期恢复发言；身份关联规则符合 ENG-ARCH |
| V-08 | `/muteinfo` 查询有处罚、无处罚、未知身份的目标 | 原因、剩余状态和错误反馈准确；不返回伪造身份或过期处罚 |
| V-09 | `/unmute` 解除禁言；对无现存禁言目标再执行 | 解除后能正常发公共聊天；重复执行明确反馈，操作日志结果准确 |
| V-10 | `/tps` 在有权和无权身份下执行 | 使用 Paper 自带实现与实际原生权限；不因只有自定义同名权限就宣称生效 |
| V-11 | `/online` 与 `/list` 入口查询 | 两入口共用 online 权限；人数与列表符合约定，玩家加入离开后更新 |
| V-12 | `/broadcast` 发送多字公告和空内容 | 有效内容按设计发送给约定接收方；空内容不发布；记录操作者与结果 |

## 3 聊天治理与权限

| 编号 | 情景 | 预期结果 |
| --- | --- | --- |
| V-13 | 在规定窗口内发送允许数量消息，再多发一条；窗口内断开重连后继续发送 | 按已允许消息计数；边界内放行，超量按 SYS-CHAT 处理；重连不清掉仍有效的窗口缓存，窗口过后恢复 |
| V-14 | 在重复检测窗口内重发上次允许的内容，并改变大小写或空白 | 比较对象为窗口内上次允许消息；判定符合 SYS-CHAT 的规范化规则，被拦截消息不更新该基准 |
| V-15 | 分别选择 cancel、warn、mute、kick 触发动作 | 每种动作只产生设计规定的处罚与提示；自动禁言时长读取配置；触发被记录 |
| V-16 | 有防刷屏豁免和无豁免的玩家做相同操作 | 只对无豁免者限流；防刷屏豁免不自动解除已有人工禁言 |
| V-17 | 被禁言玩家使用公共聊天、`/msg`、`/me` 和其他插件频道 | 公共聊天受控；其余渠道属于本版范围外，不把未覆盖渠道误报为已禁言成功 |
| V-18 | 无管理权限玩家尝试所有管理命令及别名；逐项授予命令权限再试 | 无权限不产生效果；单项授权只开放对应行为；别名和接管入口权限一致 |
| V-19 | 普通玩家、OP、控制台/RCON 分别执行短命令、插件命名空间及 SYS-COMMANDS 列明的原生命名空间入口 | 受管入口共用业务服务与审计，不留权限或日志绕过；`/tps` 按 Paper 原生权限；短命令无需依赖 `m` 前缀入口 |
| V-19a | 命令方块执行本插件管理入口；安装有命令冲突插件时再检查入口 | 命令方块明确拒绝且无管理效果；冲突按契约处理，不静默接管到错误实现 |
| V-20 | 同中转 IP 的玩家 A 被封禁，玩家 B 登录与聊天 | A 被阻止，B 不被连带处罚；插件不调用封 IP 接口、不写 IP 封禁记录 |

## 4 重启专项

| 编号 | 情景 | 预期结果 |
| --- | --- | --- |
| V-21 | 创建默认和指定时长倒计时；观察公告 | 时长、公告节点与语义按 SYS-COMMANDS；安排时记录操作 |
| V-22 | 倒计时期间重复安排、取消，再重新安排 | 同时最多一个计划；取消后不再公告或关服；重新安排可正常执行 |
| V-23 | 无权限身份安排或取消；输入非法、超范围参数 | 明确拒绝，不影响已有计划；失败结果可定位 |
| V-24 | 在已核实的外部守护下让倒计时自然结束 | 优雅停止、数据落盘、进程退出后被重新拉起；玩家可重新进入，处罚状态仍正确 |
| V-25 | 倒计时中插件禁用或服务器被维护停止 | 插件调度任务停止；维护停止方式见 OPS-DEPLOY，不产生遗留倒计时或意外反复启动 |
| V-25a | 在隔离测试环境分别模拟处罚数据保存失败、纯日志刷新失败后到期 | 前者取消计划并保持服务运行；后者明确报告审计故障，在有界等待后优雅关闭，不假称重启完成 |

V-24 必须观察真实进程退出与新进程启动，记录返回可连接状态的结果；仅看到“即将重启”公告、关服日志或一次 RCON 成功不算通过。外部守护未配置时，记录未执行并保留该交付缺口。

## 5 数据、日志与交付

| 编号 | 情景 | 预期结果 |
| --- | --- | --- |
| V-26 | 正常停止后重新加载；检查持久处罚及到期数据 | 已落定处罚保留，到期处罚不继续限制；禁言和封禁各使用 ENG-ARCH 规定的唯一存储 |
| V-27 | 管理操作成功、参数错误、无权限、目标不存在及防刷屏触发 | 按 ENG-ARCH 的类别与记录规则落日志；时间、操作者、目标、理由与结果可辨认 |
| V-28 | 在测试目录达到日志轮转条件 | 当前日志可继续写；轮转数量符合配置；无无界历史积累 |
| V-29 | 在隔离测试环境模拟处罚写盘、日志写盘失败及损坏数据 | 不静默清空有效处罚；未持久化结果不报完全成功；日志失败不反转已完成处罚，明确报告记录降级 |
| V-30 | 对含换行或控制字符的输入触发管理日志 | 一次操作不会伪造多条日志；记录格式仍可读，消息显示不执行任意指令 |
| V-31 | 核对交付包与当前说明 | 源码、可构建入口、安装 JAR、默认配置和文档齐全；实际版本与文档一致；未验证项明确列出 |

交付前应解决越权管理、共用 IP 连带封禁、处罚丢失、聊天主线程错误和无法安全完成重启等实际问题。其他已知限制按 PRD-SCOPE 的版本边界记录，不用新增通用测试框架替代必要的真实情景验证。
